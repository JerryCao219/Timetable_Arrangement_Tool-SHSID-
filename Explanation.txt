By looking at the timetable I currently have, I found that between some of my classes, the travel distance is too far, which is time consuming when students travel between floors. So I want to create a program where by inputting the student and teacher data (excel format, including their class choices and levels), the python program will auto sort out all users' timetable. I used the penalty system of the distance between each classroom and find out the best way to travel and the best time arrangement for teacher, where they teach only one subject allowing different levels. In this program, course such as CAS, Optional, and PBL are not included since they involves too much different course. 

Basically, this is how the program works: At first, the program will read the students' and teachers' data, including their names, course, and level data. Then, the program will distribute the students in the same grade into 4 blocks(just like current system, but 4 instead of 2) according the their class levels. So that the higher level student be together, which allows them to have a higher chance of being in the same class. Then, the system will distribute the teachers into these classes according to their levels, having no more than 25 students per class. Later, the system will assign classrooms, while it will redo many times to find the best solution between classroom moves. At last, the program will run the self check system, going through all the timetables and check if it fits the hard requirements while best fitting the soft requirements. 

When sorting the classes:
Get the data from each block and for each subject and level, find out the total number of students, and evenly distribute them into classes. Later on, go through all the arrangements and find out the maximum number of teachers of a same subject is needed in that period. The program will first randomize the subject teacher fitting into each class, but it might fail. So we randomize it again using a different seed. If too much attempts failed, try adding a teacher. But if the teacher number needed is greater than the actual number of teachers, the system will report problems if lack of teachers. After sorting out the classes, the program will distribute the classrooms to classes. It will randomly assign the rooms and calculate the average units of distance moves. Then it will randomize again for times and finally keeping the best solution having the least units traveled. At last, the program will run validate.py and check if there is any hard requirements unmet, meaning the system have to go over again to fix the problems of the sorted timetables.

Some of the hard requirements include: 1. Both students and teachers can have one class at a time. 2. The total time for class should be 38 units while leaving Friday afternoon blank. 3. A double class cannot be separated. 4. A same classroom cannot store 2 different classes at a time. 5. If a class appeared earlier in the day, It may not appear again(double classes does not count). 6. A student can only take a course of it's grade. 7. Some predesigned time period for course must be followed. This helps when class like PE and CAS appear and all students can have these classes the same time. 8. The sum of time unit for each course should meet it's requirements.

And some soft requirements can be: 1. Make the distance traveled the minimum by calculating room number and floor travel. In this case, a difference of 1 in room number cause 1 unit move and a floor travel cause 9 unit move penalty while room 319 and room 301 are only 1 unit since the student can travel outdoors in the building. Also, the distance will not count between period 4 and 5 since the students are having a lunch break. 2. Make the odd/even periods at least as possible, so that a student can remember their timetable easier and cause lesser confusion of "What class will I have today" 3. Let the teachers have evenly distributed number of class to teach each day.
